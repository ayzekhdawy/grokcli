# 首次运行冒烟清单（Release 前必跑）

> 来源：NEW-09（docs/plans/2026-07-26-开源诊断与整改交接.md §11）。
> 静态分析看不见「网络不可达时挂起」这类运行时问题——v0.1.7 的 5 个首跑阻断
> 全部是外部用户实测发现的。此清单在**纯净虚拟机**上手工执行，每个 release 前
> Windows / macOS 各跑一遍；Linux 至少每两个 release 跑一遍。

## 准备

- [ ] 纯净虚拟机快照（无 grok CLI、无 Node/Rust、无代理环境变量）
- [ ] 本次 release 的安装包（Windows setup + portable / macOS dmg / Linux AppImage）
- [ ] 已下载 `SHA256SUMS` 并校验通过

## A. 安装与启动

- [ ] Windows：SmartScreen 出现「未知发布者」→ README 有对应说明；「仍要运行」后正常启动
- [ ] macOS：Gatekeeper 提示与 README「damaged」章节一致；`xattr -cr` 后正常启动
- [ ] 便携版解压即用；删除目录即卸载，无残留进程

## B. CLI 闸门（NEW-03）

- [ ] **无 CLI**：SetupWizard 引导安装，多镜像可选
- [ ] **旧版 CLI（< 0.2.112，如 0.2.101）**：
  - [ ] 启动即出现 `CLI_TOO_OLD` 横幅，含「升级 CLI」按钮
  - [ ] 发消息返回 `CLI_TOO_OLD` 卡片，**不是** `AGENT_CRASHED`
  - [ ] Doctor 显示「CLI 版本过低」，**没有**裸 `unexpected argument '--'`
- [ ] **升级后（NEW-05）**：设置 → Runtime 更新 CLI 成功后出现「重启会话」按钮；点击后新会话使用新版二进制

## C. 登录（NEW-01 / NEW-04）

- [ ] **CLI 已登录 + 首启**：账号步骤第一项是「使用已有 CLI 登录（推荐）」；点击后免 OAuth 直接就绪
- [ ] **网络不可达 + Browser OAuth**（hosts 把 `auth.x.ai` 指向黑洞）：
  - [ ] 120 秒内确定性失败，提示包含代理与共享模式两条出路
  - [ ] 登录期间「取消登录」为实心主按钮、可见可点
  - [ ] 取消后可立即改走其他登录方式
- [ ] **正常网络 + Browser OAuth**：浏览器自动打开，回调后显示已登录

## D. 网络与代理（NEW-02 / NEW-07）

- [ ] 设置 → Runtime → 网络：三种模式可切换、手动地址有格式校验
- [ ] 「测试连接」逐项报告 auth / chat / api 可达性与耗时
- [ ] **Windows 系统代理**（仅注册表配置、不设环境变量）：`system` 模式下从开始菜单启动即可对话，**无需 bat 脚本**
- [ ] `manual` 模式指向本地 Clash：对话、额度刷新、CLI 更新全部走代理
- [ ] 断开代理 + `none` 模式：错误卡片出现「网络设置」按钮，点击直达网络分区
- [ ] 额度加载失败的文案区分网络问题与登录过期，且注明不影响对话

## E. 首条消息

- [ ] 新建项目 → 信任 → 发送「介绍一下你自己」→ 流式回复正常
- [ ] 权限弹窗默认 Ask；允许后工具执行可见
- [ ] 关闭应用重开：会话历史保留，可继续对话
